## FEAT-050：表格编辑（增删行列与列对齐）

| 字段 | 内容 |
|------|------|
| 实现日期 | 2026-08-29 |
| 需求描述 | 对已存在的表格执行编辑操作：在上/下插入行、删除行、在左/右插入列、删除列、整列左对齐/居中/右对齐/清除对齐 |
| 用户场景 | 写完一张表后想再加一行或一列。此前只能手工去源码里数竖线、对齐补白，列一多就极易错位；改对齐更要手写 `:---:` 并记住它属于哪一列 |
| 对标来源 | 上游 MarkText 用所见即所得的表格配合悬浮工具栏与拖拽条实现，专门有四份 e2e 规格：`drag/table-column-toolbar`、`drag/table-drag-bar`、`drag/table-row-column-menu`、`editing/table-cell-selection` |

### 实现方案

本项目是源码编辑器而非 contenteditable，所以不照搬"悬浮工具栏 + 拖拽条"，而是把**同一组操作**做成改写光标所在表格的命令。

**`lib/services/table_edit_service.dart`（新增）** —— 不依赖 Flutter，也不依赖应用状态，因此可以直接测，并且菜单（要知道命令是否适用）和编辑器（要执行它）拿到的是同一个答案。

- `locate(text, offset)`：从光标所在行向上下扩展，收集以 `|` 开头的连续行；**要求第二行是合法的分隔行**，否则不算表格——`| a | b |` 这样的两行散文不该被当成表格
- `apply(text, offset, edit)`：返回新文本与新光标位置；不适用时返回 null
- 转义竖线 `\|` 是单元格内容而非分隔符，切分时单独处理，否则整行的列会集体错位

### 若干判断

- **在表头行上执行"在上方插入行"，改为插到表头下方**。空行插在表头之前会变成新表头，整张表的列名就没了
- **表头行不能删、最后一列不能删**。GFM 表格没有表头就不是表格
- **任何一次编辑都会重排整张表**（按最宽单元格补齐，分隔行至少三个 `-`）。这是有意为之：表格在源码里也要读，某个单元格变长后整列错开比 diff 大更糟。这个形状是通行约定（Prettier 的 markdown 格式化即如此）。更窄的分隔行 `| - |` 其实是合法 GFM（本项目解析器和 marked 都认），所以三个 `-` 是约定而非正确性要求
- **中日韩字符按显示宽度算两列**。只按码元补白，含中文的表格在等宽字体下全是歪的

### 界面

- 菜单：格式 ▸ 插入 ▸ **编辑表格**，与"插入表格"并列。子菜单标签特意不叫"表格"——那样会和相邻的"插入表格"重名，用户分不清
- **不适用时置灰**，而不是留一个按下去没反应的菜单项（本项目此前在替换按钮上犯过同样的错）。可用性由光标位置实时决定
- 命令面板中带"编辑表格 · "前缀，否则"删除行"混在全部命令里看不出是什么的行
- 12 种语言文案齐备

### 涉及文件

- `code/lib/services/table_edit_service.dart`（新增）
- `code/lib/providers/editor_provider.dart`（10 个 `FormatAction`）
- `code/lib/ui/editor/source_editor.dart`（`_applyTableEdit`）
- `code/lib/ui/widgets/app_menu_bar.dart`（子菜单与置灰判断）
- `code/lib/ui/screens/home_screen.dart`（命令面板）
- `code/lib/core/i18n/l10n/*.arb`（12 种语言 × 11 个键）
- `code/test/services/table_edit_service_test.dart`（新增，23 条）
- `code/test/ui/widgets/table_menu_enablement_test.dart`（新增，4 条）

### 验收标准

- 光标在普通段落上时，全部表格命令置灰
- 光标在数据行上时可用；在表头行上"删除行"仍置灰
- 增删行列后表格重新对齐，含中文的列不错位
- 对齐命令写出 `:---` / `:-:` / `---:`，清除写回 `---`
- 一次撤销回到编辑前

## FEAT-051：块级上下移动

| 字段 | 内容 |
|------|------|
| 实现日期 | 2026-08-29 |
| 需求描述 | 把光标所在的块与上一个/下一个块互换位置；有选区时改为移动选区触及的那些行 |
| 用户场景 | 调整文章结构时想把一段挪到另一段前面。此前只能剪切再粘贴，中途还要自己处理空行 |
| 对标来源 | 上游 MarkText 的 `drag/paragraph-reorder`：把段落 A 拖到段落 B 之下，两者在 markdown 里互换顺序 |
| 快捷键 | `Alt+↑` / `Alt+↓`（各编辑器通行的组合） |

### 实现方案

上游用拖拽实现，本项目是源码编辑器，做成命令。`lib/services/block_move_service.dart`
不依赖 Flutter，可直接测试。

**块而不是行**，因为上游重排的就是块，而且"这一段"才是人心里想的单位。
块边界直接问解析器（每个 `MarkdownNode` 都带 `sourceStart` / `sourceEnd`），
不自己猜——**代码围栏里的空行看起来和块分隔一模一样**，按行移动会把围栏拆散、
把文档弄坏。表格、列表、多行段落同理，整块移动。

**有选区时改为移动选区触及的行**：选区就是读者在说"我指这几行"。

### 两个写错后才想明白的地方

1. **邻居也用块规则去找，结果邻居把被移动的行包含了进去。**
   `a\nb\nc\nd` 整体是一个段落，选中第 2–3 行往下移时，"下一个块"算出来是
   整个段落，交换后内容重复。改为：按块移动时找**下一个/上一个块**，
   按行移动时只和相邻的**一行**交换。

2. **两块之间的空行本来被当成了邻居。**
   于是第一次按键在视觉上什么都没发生，要按第二次才动。改为空行留在两块之间：
   原本是 `块 → 空行 → 邻居`，移动后是 `邻居 → 空行 → 块`。

### 顺带修掉的一处

`KeybindingService.keyForLabel` 的标签表里**没有方向键**，`Alt+Up` 解析为 null。
未解析的绑定和未绑定完全无法区分——菜单不显示快捷键、按键没反应、哪里都不报错。
补上四个方向键，并加了一条"**每个默认快捷键都必须能解析**"的测试守住它。

### 涉及文件

- `code/lib/services/block_move_service.dart`（新增）
- `code/lib/services/keybinding_service.dart`（方向键 + 两个默认绑定）
- `code/lib/providers/editor_provider.dart`、`code/lib/ui/editor/source_editor.dart`
- `code/lib/ui/widgets/app_menu_bar.dart`（段落菜单）、`code/lib/ui/screens/home_screen.dart`（命令面板）
- `code/lib/ui/screens/settings_screen.dart`（快捷键设置里的动作名）
- `code/lib/core/i18n/l10n/*.arb`（12 种语言 × 2 个键）
- `code/test/services/block_move_service_test.dart`（新增，13 条）
- `code/test/services/move_block_shortcut_test.dart`（新增，3 条）

### 验收标准

- 两段互换，再换回来得到原文档
- 代码围栏、表格、多行段落整块移动，不被拆开
- 选中多行时只移动那些行，移动后选区仍覆盖同样的文字
- 文档首块不能上移、末块不能下移
- 一次撤销回到移动前

## FEAT-052：选中文字后浮出格式工具栏

| 字段 | 内容 |
|------|------|
| 实现日期 | 2026-08-29 |
| 需求描述 | 在源码编辑器里选中一段文字，紧贴该行浮出一条小工具栏，点击按钮把选区包成粗体/斜体/删除线/行内代码/高亮/链接 |
| 用户场景 | 顺手加粗一个词，不必去记快捷键、也不必去菜单里翻 |
| 对标来源 | 上游 MarkText 的 `inline/format-toolbar`：选中即出现，点按钮包裹选区。该规格其余部分是 contenteditable 的标记折叠，本项目是源码编辑器，不适用 |

### 实现方案

`lib/ui/widgets/format_toolbar.dart`（新增）+ `SourceEditor` 里的浮层管理。

**只有六个按钮**。工具栏浮在正文之上，价值在于一眼能看完；每个命令在格式菜单里
和快捷键上都已经有了，做长了只会挡字。

**只对单行选区显示**。跨行选区上浮一条工具栏，必然盖住它所说的那段文字。

**位置是测出来的而不是估的**：用 `TextPainter` 以编辑器自己的文本样式排版该行
的前缀，所以比例字体、中日韩字符、制表符都落在它们实际所在的位置。默认贴在
被选行**上方**，上方放不下（首行、或行高小于工具栏高度时）则改到下方。
编辑器滚动时通过 `markNeedsBuild` 重算位置跟随。

### 一处"同一个数写在两处"

`_toolbarPosition` 里原本硬编码工具栏高度 36，而组件实际高 49.2，于是工具栏
会压在被选行上。改为组件导出 `FormatToolbar.height` 与 `widthFor(count)`，
定位方与组件共用同一个数，并给容器显式设高，让这个数成为事实而非猜测。

**这是位置断言逼出来的**——前面八条测试（出现、消失、点击生效）全过，
但它们完全测不到位置。

### 涉及文件

- `code/lib/ui/widgets/format_toolbar.dart`（新增）
- `code/lib/ui/editor/source_editor.dart`（浮层、定位、焦点节点、dispose）
- `code/test/ui/editor/format_toolbar_test.dart`（新增，9 条）

### 验收标准

- 光标只是光标时不出现；选中单行文字时出现；选区收起后消失
- 跨行选区不出现
- 点粗体得到 `**选中**`，点斜体得到 `*选中*`；执行后工具栏收起
- 工具栏不超出编辑器左右边界，且紧贴被选行的上方或下方
- 六个按钮都有提示文字与可用的回调
