# v1.6.3 人工测试清单

这一版目前只有三条缺陷修复，其中两条改的是**测试与注释**，不进产物。测试够不到、
需要人眼或真实网络的只有下面两项。

自动化：`dart analyze --fatal-infos lib test` 干净，`flutter test` 全绿。

---

## 一、插件市场仍然能列出插件（BUG-421 真正改到的地方）

这条改的是发给 GitHub 的 user-agent，从写死的 `MarkTextPlus/1.6.0` 改成读
`AppConstants.appVersion`。它不影响界面，但它在**每一次插件市场搜索的请求头里**，
所以一旦拼错，市场会整个打不开——而单元测试用的是假的 HttpClient，看不到这个。

**怎么造**：设置 → 插件 → 打开插件市场（或侧边栏的插件面板），点刷新。

**该看到**：列出「AI Assistant」，版本显示 `v0.1.5`，标记为 Community/Unverified。

**要留意**：如果显示「请稍候再试」之类的限流提示，那是 GitHub 的未鉴权配额
（搜索 10 次/分钟、其余 60 次/小时），不是这条改动的问题——等一分钟再点。
真正的失败长相是**空列表而没有任何说明**，或者请求直接报错。

## 二、「关于」对话框（BUG-422 挪动的注释所在的方法）

**怎么造**：菜单 → 帮助 → 关于。

**该看到**：版本号与 `pubspec.yaml` 一致。这条本来就有自动化守卫
（`about_says_this_version_test`），这里只是因为改动动了同一个文件，顺手看一眼。

- **BUG-436**（大文档抢先渲染切开 `<pre>`）：有自动化测试。

- **BUG-437**（给粗体加斜体会把粗体删掉）：有自动化测试（24 条）。
  人工要走一遍，因为它改的是**每天都在按的那几个键**：

  1. 写 `**加粗**`，**只选中中间的两个字**，按 Ctrl+I ——
     应当变成 `***加粗***`，预览里**同时是粗体和斜体**（不是只剩斜体）。
     再按一次 Ctrl+I 应当回到 `**加粗**`。
  2. 写 `~~删除线~~`，只选中中间三个字，按格式菜单里的下标 ——
     应当变成 `~删除线~`，**预览里仍是一段文字**。
     若看到一大块灰底的代码块，说明写出了 `~~~`，这条就是红的。
  3. 写两段各自加粗的段落，**一起选中**，按 Ctrl+I ——
     两段都应当变成粗+斜，**不是两段的粗体一起消失**。
  4. 照旧确认没坏：选中一句带句号的话按 Ctrl+B，句号应当留在标记外面
     （`**加粗**。后面`）；选中一个已加粗的词按 Ctrl+B 应当取消加粗。

- **BUG-438**（源码区把 `***加粗***` 染成两段）：有组件测试。
  人工顺便看一眼：按上面第 1 步写出 `***加粗***`，**源码窗格里六个星号连同中间的字
  应当是同一个颜色**（加粗色），最后那一个不应当是黑的；这一段应当同时显示为
  粗体和斜体。写 `___加粗___` 应当一样。

- **BUG-439**（`***加粗。***后面` 两个窗格说法相反）：有对账测试。
  人工顺便看一眼：写一行 `***加粗。***后面接中文`——
  **源码窗格不应当把它染成加粗色**，预览里应当就是六个字面的星号。
  再写 `***加粗***。后面接中文`（句号挪到标记外），两边都应当是粗体加斜体。

- **BUG-440**（粘贴带删除线套下标的 HTML 写出代码围栏）：有自动化测试。
  人工顺便看一眼：在浏览器里做一段「删除线里面套下标」的内容（或任何
  `<del>` 里含 `~` 的内容）复制过来，粘贴进空文档——
  **不应当出现一大块灰底代码块**，粘贴内容后面接着写的文字也应当照常显示。

- **BUG-441**（粘贴含反引号的代码会丢内容）：有自动化测试。
  人工顺便看一眼：从任意网页复制一段含反引号的代码——JavaScript 模板字符串
  `` const s = `hi ${name}`; `` 最典型——粘贴进来，**反引号应当都在**，
  整段应当仍是一个代码跨度（或一个代码块），不应当断成几截。
  再复制一段本身含有三个反引号的代码块，粘贴后应当仍是**一个**代码块。

- **BUG-442**（粘贴的表格单元格换行会拆行）：有自动化测试。
  人工顺便看一眼：在网页或 Word 里做一个表格，让**某个单元格里有两行文字**，
  复制过来粘贴——**行数和列数应当与原表一致**，表头应当仍对着下面的列，
  那个单元格里的两行应当变成一行里的两段话（中间有空格，不是粘在一起）。

- **BUG-443**（粘贴的链接被自己的网址或文字截断）：有自动化测试。
  人工顺便看一眼：复制一个**网址里带空格或不成对括号**的链接（SharePoint 路径、
  带空格的文件名最典型）粘贴进来——**应当还是可点的链接，地址完整**；
  再复制一个**链接文字里带方括号**的链接（如「see [1] here」），
  粘贴后应当仍是链接而不是一串字面字符。最后复制一张**带链接的图片**
  （缩略图），粘贴后应当仍是图片且仍可点。

- **BUG-444**（粘贴的斜体／粗体被内容里的星号截断）：有自动化测试。
  人工顺便看一眼：在网页上做一段**斜体、且内容里含一个星号**的文字
  （如斜体的「3*4」）复制过来，粘贴后**整段应当都是斜体**，不应当只斜一半、

- **BUG-445**（导出写得出、粘贴读不回）：有对账测试（48 条）。
  人工顺便看一眼：写一篇含**带提示的链接**（`[t](https://x "提示")`）、
  **行内与块公式**、**一处脚注**的文档，导出 HTML，把导出的内容整段复制再粘贴回
  一个空文档——这四样都应当**还在**：链接仍有提示、公式仍是公式（不是一对括号）、
  脚注仍是脚注（不是上标加链接）。

- **BUG-446**（`src` 匹配到 `data-src`）：有自动化测试。
  人工顺便看一眼：从一个**图片懒加载**的网站（多数新闻站、博客）复制一张带图的段落
  粘贴进来——**图片应当能显示**，而不是一个 1×1 的占位符。
  再从任意网页复制一段带图带链接的内容，地址应当都对。

- **BUG-447**（「复制为 HTML」写出的不是编辑器的 HTML）：有 16 条测试。
  人工顺便看一眼：选中一段**含列表或表格、含链接、含 `a < b`** 的内容，
  用菜单的「复制为 HTML」，粘到任意文本编辑器里看——
  **列表应当是 `<ul><li>`、表格应当是 `<table>`、链接应当是 `<a href>`，
  `<` 应当写成 `&lt;`**。再选中 `**加粗。**后面` 复制为 HTML，
  它**不应当**变成 `<strong>`（预览画的是字面星号，两边要一致）。

- **FEAT-153 / FEAT-154**（正则查找按行锚定、替换可用 `$1`）：有 25 条测试。
  人工要走一遍，因为它改的是查找栏的行为：

  1. 打开查找（Ctrl+F），点亮 `.*`，查 `^#+ ` ——
     **应当找到文档里的每一个标题**，而不是零个或一个。
  2. 展开替换行，查 `\[(.+?)\]\((.+?)\)`、替换为 `$2: $1`，
     按「替换」改一处、按「全部替换」改全部——**文字与地址应当对调**。
  3. 正则开启时，替换框空着的时候提示里应当能看到 `$1  $&`。
  4. 照旧确认没坏：**关掉** `.*`，查 `cost` 替换为 `$5`——
     **应当写出字面的 `$5`**，不是空的。
  5. 「全词」按钮在 `.*` 点亮时应当是灰的（原有行为）。

- **BUG-448**（AI 端点以 `/v1` 结尾会被拼成 `/v1/v1/`）：有 11 条测试。
  人工顺便看一眼：设置 → AI，端点填 **`https://api.openai.com/v1`**（或你在用的
  服务商文档里给的那个 base URL，它们几乎都带 `/v1`），填好模型与密钥后按
  「测试连接」——**应当连得上**，而不是 404 / 「模型不存在」。
  再把端点改成不带 `/v1` 的 `https://api.openai.com` 重试一次，**两种都应当能用**。

- **BUG-449**（插件设置页里写死的英文）：有扫描守卫。
  人工顺便看一眼：把界面语言切到中文，打开一个**没有设置项**的插件的设置页
  （例如任何 `runtime: data` 的插件，或把某个插件的 `settings` 清空）——
  那一句应当是**中文**「…没有可配置的设置。」，不是 `has no settings.`。

- **BUG-450**（「还没配好 AI」是英文，且让人查三个字段）：有 10 条测试。
  人工要走一遍，因为它是**第一次用 AI 功能必然撞到**的那一步：

  1. 界面语言切到中文，设置里**把 AI 关掉**，运行 AI 插件的任意命令——
     提示应当是中文「请先在设置里打开 AI 功能。」
  2. 打开 AI、**三个字段都留空**，再运行——应当只提示**端点**（最上面那个字段），
     不是把三个都列出来。
  3. 填好端点、留空模型 → 提示模型；填好模型、留空密钥 → 提示密钥。
  4. 设置页按「测试连接」，同样三步应当给同样的中文提示。
  5. **确认没坏**：三个都填好但密钥是错的，按「测试连接」——
     应当显示**供应商自己返回的英文错误**（那条不翻译，它说的比我们多），
     且「复制」按钮复制到的就是那一段。

- **BUG-451**（打错的图表在导出与全屏里显示英文错误面板）：有 6 条测试。
  人工顺便看一眼：界面语言切到中文，写一个**打错的** Mermaid 图表
  （把 `graph TD` 写成 `grahp TD`）——
  1. 预览里的错误框应当是中文（原本就是）；
  2. **点图表放大到全屏**，错误框也应当是中文；
  3. **导出 PDF**，打开 PDF 看那一处——应当是中文错误框，
     不是 `Mermaid parse error / Unrecognised diagram type`。Word 与 HTML 同理。
  4. 确认没坏：错误里被打错的那个词（`grahp`）与可用类型名（`flowchart` 等）
     **应当保持原文**，不能被翻译——它们是要照着打出来的东西。

- **BUG-452**（撤销历史按步数限，大文档能占到 GB）：有 5 条测试。
  人工要走一遍，因为它改的是**撤销键的行为边界**：

  1. 打开一个**几 MB 的 Markdown 文件**，在里面改十几处（每处之间停一下，让快照落下），
     看菜单/`get_state` 里的内存读数——**不应当随编辑次数线性暴涨**。
  2. 在那个大文档上按 Ctrl+Z：**至少能退回一步**（不能变成按了没反应）。
  3. **确认没坏（最重要的一条）**：打开一个**普通大小的笔记**（几十 KB），
     连续做几十次编辑再一路 Ctrl+Z——**应当和以前一样能一路退回去**，
     步数没有变少。
  4. Ctrl+Y / Ctrl+Shift+Z 重做应当照旧工作，能一路走回最新状态。

- **BUG-453**（每次选区变化都拷贝整个选区）：有 7 条测试。
  人工要走一遍，因为它改的是**「当前选区」这件事本身**：

  1. 打开一个**几 MB 的文档**，在开头按住 **Shift+↓** 一直扩选到很深——
     **应当一路顺畅**，不是越选越卡。
  2. 选中一段文字，运行 AI 插件的「翻译选中内容」——**插件拿到的应当正是那一段**。
  3. **分屏模式下的关键一条**：在**预览**里拖选一段，运行插件——拿到的应当是
     预览里选的那段；然后**把光标点回源码区**（不选任何东西）再运行——
     应当提示「没有选中内容」，**不能**把预览里刚才那段又交一次。
  4. 反向：源码区选一段、运行插件（拿到源码区那段）；再去预览拖选另一段、运行——
     应当拿到预览那段。
  5. 预览里选中一段按 Ctrl+C，粘到 Word 里应当仍带格式（富文本复制走的是同一个值）。

- **BUG-454**（大文档里每按一次方向键要切两遍全文）：有 12 条测试。
  人工要走一遍，因为它改的是**移动光标**这件最基本的事：

  1. 打开一个**几 MB 的 Markdown 文件**，**按住方向键**在里面跑——
     **应当顺畅**，不是一格一格地卡。
  2. **确认表格菜单没坏**：在文档里做一个表格，把光标放进表格的**数据行**，
     打开「格式 ▸ 插入 ▸ 编辑表格」——各项应当**可用**；
     把光标移到表格外的普通段落，同一个子菜单里各项应当**置灰**。
  3. 光标放在**表头行**：其余可用，但「删除行」应当置灰（没有表头就不是表格）。
  4. **预览模式下**（不是分屏）打开那个子菜单——各项应当**置灰**。
     这一条是本次新行为：以前它会按源码窗格最后报告的位置点亮，
     而那个位置在预览里读者看不见。

- **BUG-455**（「查找下一个」为定位一个匹配而重排整个前缀）：有 7 条测试。
  人工要走一遍，因为它改的是**跳到匹配**时落在哪里：

  1. 打开一个**几 MB 的 Markdown 文件**，搜一个**在文件后半部分**出现的词，
     连按「查找下一个」——**每次都应当立刻跳到**，不是等一两秒。
     （改之前，4 MB 文档上每按一次冻结约 2.3 秒。）
  2. **确认落点没坏**，这条最重要：开**分屏**（窗格更窄，长行会换行），
     在有**很长的段落**的文档里搜一个词，跳过去之后**匹配那一行应当在视口里**，
     大约三分之一高的位置——**不是**屏幕外、也不是在更上面。
  3. **预览模式**下搜索并跳转，仍应滚到对应位置（走的是另一条路，没有改）。
  4. 顺带：**行号列**仍应与文字对齐（删掉了一个包着编辑区的 LayoutBuilder）。

- **BUG-456**（格式工具条按行号定位，换行或滚动后浮在别处）：有 2 条测试。
  人工要走一遍，因为它是**肉眼一看就知道对不对**的那种：

  1. 开**分屏**，在有**很长段落**的文档里，选中**某个长段落下方**一行里的几个字
     ——格式工具条应当**紧贴在选中文字上方**，不是飘到上面几行去。
  2. **滚到长文档的深处**（几百行），选几个字——工具条仍应贴着它，
