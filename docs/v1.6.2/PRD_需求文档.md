## FEAT-125：插件详情页说明它被允许做什么

| 字段 | 内容 |
|------|------|
| 实现日期 | 2026-09-05 |
| 需求描述 | 权限从 v1.6.2 起真的会拦人（BUG-262），读者需要一个地方看到被拦的依据是什么 |
| 用户场景 | 装了一个插件，某个功能点了没反应；或者装之前想知道这个「Community / Unverified」的东西要碰什么 |
| 实现方案 | `PluginCatalogEntry` 带上 `permissions`，`installed` 工厂从本地 manifest 填。详情页头部之下一段 Permissions，每条一行，用 `PluginPermission.describe()` 的人话而非标识符。拒绝通知同样两样都给：句子给读者，标识符给写 manifest 的人 |
| 验收标准 | 已安装插件的详情页列出它声明的每一项，说的是「Read the open document and your selection」而不是「document.read」；声明为空时明说「asks for nothing」；不认识的权限照样占一行并说明本版本不为它授予任何东西；**搜索结果不显示这一段**——包还没下载，编辑器没见过 manifest，说不出它要什么，空着比猜错好 |
| 涉及文件 | `lib/models/plugin_catalog_entry.dart`、`lib/ui/screens/plugin_detail_view.dart`、`lib/services/plugin_command_service.dart` |

### 一个没有做的决定

装之前展示权限，需要在下载并校验 ZIP 之后、启用之前插一个确认步骤——浏览器扩展就是这么做的，那才是真正的事前披露。

这一版没有做，因为它是产品决策而不是缺陷修复：它给安装流程加了一道门。展示是纯增益，加门不是。留给用户定夺。

## FEAT-126：单个插件窗格可以上下分割，方向由插件选

| 字段 | 内容 |
|------|------|
| 实现日期 | 2026-09-07 |
| 需求描述 | 标签页里只有一个插件窗格时，除了左右分割，还要能上下分割。默认左右；插件自己选；读者可以翻转。官方插件的 AI 写作与 AI 纠错用上下 |
| 用户场景 | 让模型改写一段话，改写结果与原文并排时是两条窄栏，要在两栏之间来回看才能对照。放在下面则行宽相同，眼睛往下扫就能比较——这正是 diff 工具把两版上下放的理由 |
| 实现方案 | 插件用它填的槽位表达方向：`bottom` 是上下，其它是左右（默认）。读者用窗格标题栏那个 `swap_vert` 按钮翻转，翻转后以读者的选择为准（`_paneBelow` 记住它）。三宫格早就有这个按钮，只是二宫格原先没有可翻的东西 |
| 涉及文件 | `lib/ui/widgets/plugin_panes.dart`；`test/ui/widgets/plugin_panes_layout_test.dart`；插件仓库 `plugin.lua`；`.claude/CLAUDE.md` |
| 验收标准 | 只填 `bottom` → 文档在上、窗格在下，宽度不被切；填 `right` 或 `corner` → 左右分割，高度不被切；两种形态下标题栏都有翻转按钮，按了真的换向 |

### 这条改掉了一条写着「定死，别再改」的规范

`.claude/CLAUDE.md` 原文是「**只填一个窗格时一律左右分割**——一个窗格就是一个窗格，不管它自称什么」，还有「二宫格没有第二行……所以那两种形态下不画这个按钮」。

那条理由对**哪一个**窗格成立（只填 `corner` 不该留两个空格子），对**哪个方向**不成立。人工测试指出来之后规范跟着改了，并在 CLAUDE.md 里写明了改动日期和原因——否则下一轮我会按旧规范把它改回去。

**还有一条测试的名字就是那条旧决定**：`one pane splits the width, whichever slot it claimed`。它现在叫 `one pane goes under the document when it asked for bottom`，注释里留着它原先为什么那样写。
