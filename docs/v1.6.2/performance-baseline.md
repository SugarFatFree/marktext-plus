# 性能基线（2026-09-09 实机测量）

「轻量级、秒启动、占用低、加载快、支持大文件」是这个编辑器的第一条主张。
在此之前没有可对照的数：改动是否牺牲了大文件表现，无从判断。这份文档记下
一次实机测量的结果和**复现办法**，供以后对比。

测量在真实运行的应用上通过自动化接口进行（开标签 → 读日志里的 `preview drew` 行），
不是本机跑测试。

## 一、渲染耗时

| 文档 | 块数 | 绘制耗时 | 每块 |
|------|------|---------|------|
| 16 KB | 121 | 93 ms | 0.77 ms |
| 74 KB | 541 | 507 ms | 0.94 ms |
| 165 KB | 2281 | 2219 ms | 0.97 ms |
| 986 KB | 7201 | 6986 ms | 0.97 ms |

**每块耗时稳定在 0.77–1.08 ms，与文档规模无关**——这正是
`cost_stays_linear_test` 在本机保证的线性，在实机上得到了印证。
以后若某次改动让这一列显著上升，就是退化。

> 这批数字里 312 KB 那一行被删掉了：它报的是前缀而非整篇（BUG-361），
> 当时无法与其余行相比。修复在 `765a68e`，装上该版本之后测得的数才可信。

## 二、常驻内存

- 起点（只开一篇 8.6 KB 文档，应用已运行数小时）：**1391 MB**
- 一篇 986 KB 文档解析期间的峰值：**2584 MB**
- 90 KB 文档反复开关四轮，较起点：**+23 / +84 / +78 / +86 MB**

第三、四轮与第二轮持平，不是每轮等量累加，**没有逐轮泄漏的迹象**；
两次测量之间起点自己从 2628 MB 落回 1391 MB，说明内存会还回去。
涨上去之后不立刻回落是 Dart 持有空闲页的正常表现。

需要留意的是**起点本身偏高**（1391 MB）。这台实例被自动化连续驱动了很久，
不代表冷启动后的占用；冷启动占用应当另测一次，本文档还没有那个数。

## 三、怎么复现

1. 应用运行中，通过 MCP 的 `control` 动作 `new_tab` 送入指定大小的文档
2. 等几秒，用 `read_logs` 找 `preview drew N blocks in N ms (N MB resident)`
3. 关掉标签，另开一篇小文档触发一次绘制，读它报的常驻内存

要点：**每篇文档只会留下一条 `preview drew` 行**，且必须确认读到的是这次的、
不是上一篇的——按时间戳对，不要只取末尾一条。
