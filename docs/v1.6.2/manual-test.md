# v1.6.2 人工测试清单

自动化测试 2821 条全绿，`dart analyze --fatal-infos` 干净。**这份清单只列测试够不到的地方**——视觉、真实文件系统、真实插件、别的应用。纯内部收敛（围栏规则、配置解析等）不在这里，它们由测试和变异验证覆盖。

按「怎么造出这个场景 → 该看到什么」写，可以照着做。

## 一、看一眼就能判断的（视觉）

### 1. 打开 `code/test/fixtures/showcase.md`，切到源码视图

这一版给源码窗格加了五种以前不染色的标记。第 16 行那一行是关键：

```
~~strikethrough~~, ==highlight==, ^superscript^, ~subscript~, and a
```

**该看到**：`~~删除线~~` 有线，`==highlight==` 有黄底，`^superscript^` 和 `~subscript~` **仍然是普通文字**（有意的，源码窗格改不了字号）。

再看：`_下划线写的斜体_`、`__这样的粗体__`、`$E = mc^2$`（代码色）、`[^1]`（链接色）、`++下划线++`。

**要留意**：`snake_case_name` 这类标识符**不能**变成斜体。文档里出现价格 `$5` 和 `$10` 时，中间的文字**不能**被染成公式。

### 2. 行内代码的底色现在紧贴文字 ← **这条要你定**

以前 `` `code` `` 前后各加了一个空格来撑开底色。那两个空格是**内容**：会被一起复制走，而且打开查找框时它们就不加了——同一段文字在开不开查找框时长度不同。

现在去掉了，底色贴着字母。**如果你觉得太挤**，可以退回去，但要连带接受上面三个后果，或者改成 `WidgetSpan`（那样代码文字就选不中、搜不到了）。

### 3. 插件详情页多了一段「Permissions」

设置 → 插件 → 点一个已安装的插件。**该看到**：README 上方一段权限列表，每条是一句人话（"Read the open document and your selection"），不是 `document.read` 这样的标识符。

社区搜索结果的详情页**不该**有这一段——包还没下载，编辑器没见过它的 manifest。

## 二、要造场景才能验的

### 4. 装一个 manifest 有毛病的插件

随便改一个插件的 `manifest.json`：把 `"runtime": "lua"` 改成 `"perl"`，或者把 `entrypoints` 里的 `windows` 打成 `windwos`。

**该看到**：插件设置页在已安装列表**下方**出现「Installed but unreadable」，一行一个：目录名 + 具体原因（"unknown plugin runtime: perl"）。以前它是静默消失的，和从没装过一模一样。

### 5. 装一个什么权限都不声明的插件

把某个插件 manifest 的 `"permissions"` 改成 `[]`，然后用它。

**该看到**：它拿不到文档内容（看到的是空文档），开不了窗格，弹不了通知——而且**每次被拒时都会告诉你**缺哪一项，用一句人话加上标识符。

### 6. 制造一次磁盘冲突 ← **这条最要紧**

在编辑器里打开一个文件、改几个字**不要保存**；用别的程序（记事本、`echo x > 文件`）改同一个文件；回到编辑器等自动保存或按 Ctrl+S。

冲突横幅出来后，三个选择都要试：

- **「用我的覆盖」写不进去时**（可以把文件设成只读来造）：该弹出失败原因，**而且横幅要留着**。以前是横幅消失、磁盘上还是对方的版本——看起来像成功了
- **「用磁盘上的」读不了时**（把文件删掉再点）：该说为什么，而不是什么都不发生
- 状态栏点编码换一种重读，如果文件已经不在了：同样该说原因

### 7. 手工改坏配置文件

配置在系统应用支持目录下的 `config.json`。把任意一个 `true`/`false` 改成 `"yes"`，或者把 `"recentFiles"` 里塞一个数字进去。重启。

**该看到**：只有那一项回到默认，**其余设置全都还在**（主题、字体、快捷键、最近文件）。以前一个字符写错就全部重置。

## 三、要别的应用配合的

### 8. 导出 Word，看 `==高亮==`

写一行 `==标出来== ^上标^ ~下标~ ++下划线++ ~~删除线~~ \`代码\``，导出 .docx，用 Word/LibreOffice 打开。

**该看到**：高亮是黄色荧光笔（以前它**完全没有底色**，是这一版修的），其余五种各自的样式都在。

### 9. 从网页复制粘贴

找一个带 `<mark>`、`<sup>`（维基百科的脚注引用就是）、`<u>` 的页面，复制一段粘进编辑器。

**该看到**：它们变成 `==...==`、`^...^`、`++...++`，而不是丢掉标记只剩字。**含空格的短语**（`<sup>the note above</sup>`）应该保持纯文本——那种写法编辑器自己读不回来。

这一版重写了粘贴前剥掉注释和 `<script>`／`<style>` 的那两段（原来是正则，在畸形输入上是二次方）。**自动测试用的是我构造的 HTML**，而浏览器真正放进剪贴板的东西不一样：Windows 会包一层 `HTML Format` 头，Chrome 会插 `<!--StartFragment-->` 这样的标记，页面本身还常带内联样式表。所以这一条要用**真实的浏览器复制**，不要用手写的 HTML 片段。

**该看到**：粘进来的是正文，没有 `StartFragment` 之类的碎片标记，也没有整段 CSS 混进文字里。多试一个样式表在正文之前的页面（多数新闻站是这样）。

### 10. 复制含公式或图片的段落，粘到 Word

在预览里选中一整段（段落里要有 `$E = mc^2$` 或一张图或 `` `代码` ``），复制，粘到 Word。

**该看到**：粗体、链接、标题都在。以前只要段落里有这些，**整段的格式全丢**，只剩纯文本。

### 11. 从源码窗格复制带 HTML 标签的文字

设置里**关掉**「行内 HTML」。源码里写 `a <b>tagged</b> word`，从源码窗格选中复制，粘到 Word。

**该看到**：`<b>` 是字面文字，和预览里一致。以前从源码窗格复制会变成粗体，从预览复制不会——同一段源码，取决于你在哪个窗格里拖的鼠标。

---

### 12. 退出应用，看 trace 日志

关掉应用，打开配置目录里的 `startup-trace.log`，看最后一次运行的末尾。

**该看到**：`window destroyed` 之后就结束了。**不该看到** `still running 100ms after close began` 这类行——那说明关闭看门狗没被撤下，而它在 600ms 时会 `exit(0)`，抢在正常退出前面。

## 四、插件自绘界面与网络（2026-09-07 新增）

这一段是这批改动新长出来的能力和闸门，测试够不到的部分。做这几条要一个能改
manifest 的插件——把官方插件复制一份、改 id 和权限即可。

### 13. 一个插件画出自己的界面

让插件返回一棵组件树（`sdk.ui.column{ ... }`），八种节点各放一个：
`text` / `input` / `chips` / `button` / `select` / `checkbox` / `markdown` / `image`。

**该看到**：画在**启动它的那个容器**里——从右侧边栏点开就画在抽屉里，
从右键菜单启动就画在悬浮卡片上。跟随主题（切到深色主题不该有白底残留）。
按下按钮后，`on_event` 收到的 `values` 里**每一个输入都在**，包括你没碰过的。

**不该看到**：半个表单。节点名拼错、树超过 12 层或 500 个节点，应该整棵拒绝并报错。

### 14. 图片的三种来源

`image` 节点的 `source` 分别试：`data:` URI、插件目录里的相对路径、`http(s)` 地址。

**该看到**：前两种直接显示。绝对路径（`/etc/hostname`）被拒绝并说明原因。

### 15. 没申请 `network.request` 的插件，取不到远程图片 ← **这条是闸门**

把插件 manifest 里的 `network.request` **删掉**，其余不动，重装。

**该看到**：`image` 节点显示一行错误，说这个插件没有申请 `network.request`。
`markdown` 节点里写 `![](http://…)` 也一样——**这两种写法必须给同一个答案**，
上一版里后者能绕过去。

打开配置目录的 `plugin-logs/<插件id>.log`：**该看到**一行 `refused`，带主机名。
被挡住的尝试和成功的请求一样要留痕。

把权限加回去重装，两种写法都该正常取到图。日志里这次是
`image https://<主机> 200 <字节>B <毫秒>ms`——**只有主机名，没有路径和查询串**。

### 16. 权限清单显示隐含的那一条

装一个只声明 `ui.webview` 的插件（webview 本体这一版没有，但权限还在）。

**该看到**：详情页的 Permissions 里**有两行**——web view 那条，和
「Send requests to any server it chooses」。声明了一条，读者看到两条，
因为前者带着后者。

**顺便把面板拖窄**（拖到 400px 以内）：每条说明应该**折行**，不能横着跑出边界。
webview 那句 88 个字符，是这里最长的。

### 17. 代理环境下的远程图片

如果你在代理后面（`http_proxy` / `https_proxy` 有值）：新建文档写
`![](https://raw.githubusercontent.com/…/任意图片)`，切到预览。

**该看到**：图能出来。以前这里是错误色的 `[alt 文本]`——看起来像链接坏了，
其实是那条请求从没走代理。同一条改动也覆盖更新检查。

`no_proxy` 里列的主机应该照常直连。

## 五、几秒钟就能验的（2026-09-08 新增）

这一段全是**十秒内能看出对错**的，而且每一条以前都是错的。先做这一段，
它比前面任何一节都快。

### 18. 列表里留一条空的

在任意文档里写：

```
- 第一条
-
- 第三条
```

**该看到**：三条平级的项。**以前**第三条会缩进一层，变成第二条的子项；
再多留一条空的就缩进两层。

`- `（横杠加一个空格，什么都不写）也一样——**那正是按回车续列表时留下的形状**，
所以不用刻意去写就会遇到。

顺便：在空条目上**再按一次回车**，标记应该被去掉、退出列表。

### 19. 按 F5「重新加载图片」

打开一个引用了网络图片的文档（`![x](https://…)`），切到预览，按 **F5**
（或菜单里的「重新加载图片」）。

**该看到**：图片重新请求一次。**以前这个菜单项和快捷键完全没有反应**——
不是失败，是什么都不做。

验证办法：把图片地址换成一个会变的（比如某个随机图 API），按 F5 看它变不变。

### 20. 在设置里改代码字体或字号

打开一个有代码块的文档，切到预览，**保持预览开着**，去设置里把
「代码字号」从 14 改成 24。

**该看到**：预览里的代码块立刻变大。**以前纹丝不动**，要等别的事情（改主题、
打字）碰巧刷新了缓存才会跟上。代码字体同理。

### 21. 改一个图表的数据

在文档里放一个图表，标题不动，只改数据：

````
```mermaid
xychart-beta
    title "销量"
    x-axis [一月, 二月, 三月]
    bar [10, 20, 30]
```
````

把 `[10, 20, 30]` 改成 `[90, 90, 90]`。

**该看到**：柱子跟着变。**以前不会**——只要标题没变，图就认为自己没变过。
`kanban`、`radar`、`quadrantChart` 三种图表也是同样的毛病，同样已修。

### 22. 在设置里改一项，重启看它还在不在

随便改几项设置（主题、字号、编辑器最大宽度、是否显示段落数），完全退出应用再打开。

**该看到**：全都还在。这一条没有已知缺陷，但它是**唯一能发现「某项设置存不住」的办法**，
而那类失败不报任何错。

## 六、这一轮改动的验证（2026-09-08 下午新增）

这批改的是**快捷键、命令面板、分屏编辑**——三处都是「测试跑得过、手感对不对要人按一遍」。

### 23. 那十一个原本按了没反应的快捷键 ← **这条是闸门**

BUG-330 之前，这些键在菜单里画着、在设置里能改，**按下去毫无反应**。
一个一个按：

| 键 | 该发生什么 |
|----|-----------|
| Ctrl+= / Ctrl+- | 正文字号变大 / 变小 |
| Ctrl+0 | 字号回到 16 |
| F11 | 全屏切换 |
| Ctrl+P | 弹出打印对话框 |
| Ctrl+, | 滑入设置页 |
| Ctrl+Shift+N | 开出第二个窗口 |
| Ctrl+Q | 退出（有未保存内容时应当先问） |

**顺带要看的**：Ctrl+Q 必须走「问未保存」那条路。如果它直接退掉丢了内容，
那是比原来更糟的回归，立刻停下报回来。

### 24. 改一个快捷键，然后按新键

BUG-335：以前改完之后**菜单显示新键、按下去还是旧键**。

1. 设置 → 快捷键，把「加粗」改成 `Ctrl+Shift+B`
2. 回到文档，选中一个词按 `Ctrl+Shift+B` → **该加粗**
3. 按原来的 `Ctrl+B` → **不该再加粗**
4. 点「恢复默认」，再按 `Ctrl+B` → **又该加粗了**

### 25. 命令面板里搜得到这些命令了

Ctrl+Shift+P，搜 `zoom`、`print`、`export`、`full`、`quit`。
FEAT-130 之前这些**一条都搜不到**。

**每条右侧应当显示它当前的快捷键**；上一条里改过的绑定，这里也该跟着变。

### 26. 分屏里勾复选框

BUG-337。文档里写 `- [ ] 一`，切到分屏：

1. 在**右半边（预览）**点那个方框 → 该勾上，**左半边源码同步变成 `- [x]`**
2. 紧接着按 Ctrl+Z → **该撤回这一勾**
3. 状态栏的行列号应当是活的，不是停在旧位置

### 27. 行内 HTML 开关立刻生效

BUG-336。文档里写 `press <kbd>Esc</kbd> to stop`，用预览模式：

1. 设置里关掉「启用 HTML」→ 预览里能看到字面的 `<kbd>`
2. **不要碰文档**，去设置里打开它，回来看预览 → `<kbd>` 该消失了

以前要**等下一次敲键**才更新。

### 28. Windows 上连续保存（只在 Windows 上做）

BUG-338 加的是守卫不是改动，但那段重试只在 Windows 上会被真正用到。
装了杀毒软件的机器上，快速 Ctrl+S 十来次，**不该出现任何一次保存失败提示**。

### 29. 断网点「检查更新」

BUG-339。拔网线或关 Wi-Fi，菜单 → 检查更新。

**该看到**「检查失败」之类的话，**绝不能说「已是最新版本」**。
接回网络再点一次，应当给出真实答案。

## 七、读者实机报告之后（2026-09-08 傍晚新增）

### 30. 那个「已安装但读不出来」的残留插件 ✅ 读者已确认清除

诊断结果：机器上是**两个不同 id 的插件**——

| id | 状态 |
|----|------|
| `com.marktextplus.ai-translate` v0.1.4 | 正常，四个命令都在 |
| `com.sugarfatfree.ai-translate` | 读不出来的旧目录 |

「之前的插件也能用」说的是前一个。后者是残留。

**做**：在「已安装但读不出来」那一行右侧点垃圾桶按钮删掉它，重启。
**该看到**：那一段整个消失。

**顺带验证 BUG-345**：删之前，用 MCP 的 `read_logs`（或看日志文件），
**应当能查到一条**写着是哪个键出了问题。以前那里一个字都没有。

### 31. 右侧边栏的提问不再是弹窗

**做**：点右侧边栏的 AI 助手图标。
**该看到**：抽屉打开，**问题就问在抽屉里**——问题文字、可选项、
一个已经填好上次答案的输入框、取消/确认。按 Enter 直接提交。

**不该看到**：浮在文档上的卡片在问，而答案落到抽屉里。

**对照组**：从**菜单**或右键菜单启动同一个命令，**仍然用卡片**——
那里没有属于它的地盘，卡片是对的。

### 32. 插件搜索不再每次启动都去问 GitHub ✅ 实机已确认（不再报限流）

**做**：开编辑器 → 看插件面板（会搜一次）→ 关掉 → 再开 → 再看。
**该看到**：第二次**立刻出结果**，没有等待，也不该再撞限流。

**做**：点刷新按钮。**该看到**：它真的去重新问了（会有等待）。

**造限流**：六小时内反复点刷新可以把配额用光——那时的错误提示应当仍然
说得清楚（「819 秒后再试」这类），而不是显示成「没有找到插件」。

### 33. MCP 能跑插件命令了（FEAT-131 + BUG-352）

**BUG-352 说明**：读者装的 `cc302b0` 里这个动作是坏的——
接口报出四个命令，用它自己报的名字去调却说「没有这个命令」，
理由后面跟着一片空白（查了另一个字段）。修在 `42bf07d`，**要装那之后的版本才对**。

用 MCP 发：

```json
{"action": "run_plugin_command",
 "pluginId": "com.marktextplus.ai-translate",
 "command": "ai.write"}
```

**该看到**：命令真的跑起来（和点菜单一样），`isError` 为 false。

**故意写错命令名** → 回话里应当**列出它实际有的命令**（`ai.write, ai.proofread,
translate.selection, translate.document`），**不能是空的**，且 `isError` 为 true。

**用 `get_state` 报的每一个命令名各跑一次** —— 四个都该被接受。
接口报得出而接受不了，正是 BUG-352。

### 34. 拒绝就是拒绝（BUG-343）✅ 实机已确认

用 MCP 发一个必然失败的请求，例如激活一个不存在的标签。
**该看到**：句子说明原因，**并且 `isError` 是 true**。
以前每一次拒绝都写着成功。

## 八、三条主张，现在有数字了（2026-09-08 晚新增）

装上这一版之后，日志里会出现三种以前没有的行。用 MCP 的 `read_logs`
或看配置目录里的日志都行。

### 35. 启动有多快

开一次编辑器，看日志：

```
[INFO ] [startup] app root built (theme and locale resolved) at 218 ms (142 MB resident)
[INFO ] [startup] home screen first build at 412 ms (159 MB resident)
```

**该看到**：两条，各带毫秒和内存。**不该看到**四十条——
细节标记仍然只进 `startup-trace.log` 文件。

### 36. 一份大文档画多久、占多少

开一个几万字的 md，切到预览。日志里该出现：

```
[DEBUG] [preview] preview drew 1200 blocks in 47 ms (203 MB resident)
```

**这是本版唯一能回答「大文件表现如何」的东西。**
开一份小文档（几十行）**不该有这条**——它一批就画完了，没有填充可计时。

### 37. 换一份更大的，数字要跟着长

同一次运行里先开小的、再开大的，两条 `preview drew` 的
块数、毫秒、内存应当都随之增长。**这三个数一起看才有意义**——

### 41. 大文档在画完之前不装作画完了（BUG-361 / BUG-362）

需要一篇**超过 1500 行**的 Markdown（普通文档很容易到；实在没有就把一份长文档

1. 打开它，**立刻滚到底**
2. 底部应当一直转着**加载指示器**，直到整篇真的画完
   - 修复前：画完顶部那一段就收起了指示器，而下面还有大半没画
3. 指示器还在时，底部**不该**出现「点这里接着写」的空白落点

[preview] preview drew N blocks in M ms (K MB resident)

同一篇文档两次打开还能给出两个不同的数。

### 42. 切换标签页回来，回到原来读到的位置（FEAT-137）

需要**两篇都能滚动**的文档，各开一个标签。

**源码模式**：

1. 在标签 A 滚到中间，记住看到的是哪一段
2. 切到标签 B，**它应当在自己的顶部**，不是继承 A 的位置
3. 切回 A —— 回到刚才那一段

**预览模式**：同样三步。特别拿一篇**很长的**（几百段以上）试：
滚到很靠下的地方再切走切回，应当**回到很靠下的地方**，
而不是停在文档上方某处——预览是跨帧画出来的，恢复太早会被夹到刚画好的那一点高度。

**分屏模式**：源码那半记得位置；预览那半跟着源码走，不自己恢复。

**再看几处不该被打扰的**：

| 情形 | 该发生什么 |
|------|-----------|
| 从搜索结果点进某一行 | 去**那一行**，不是回到上次读到的地方 |
| 从大纲点某个标题 | 同上 |
| 第一次打开的标签 | 在顶部 |
| 标签关掉再重新打开同一个文件 | 在顶部（记忆随标签一起释放） |
| 切走期间窗口被拉小、字号调大 | 回来时仍在文档内，不会跑到文档外面 |

> 跨会话不记：关掉应用再打开，位置不保留。这一版只做会话内的标签切换。

4. **把同一个要求提两次**（比如连说两次「短一点」）——历史里应当是**两条**，
   而不是后一条盖掉前一条（BUG-399）
5. **选中一段再写作，然后采用（BUG-402，最要紧）**——只应替换你选中的那一段。
   修复前会**用答案覆盖整篇文档**；我在 BUG-395 的修复引入了这个回归，
   现在有测试钉住了，但请你实机确认一次
6. **让插件做它没申请权限的事**（比如改一个 manifest 去掉 `ui.sidebar`），
   弹出的提示应当是**中文**（BUG-401），修复前是英文
7. **在分屏模式下，新开一个空白标签页写作再采用（BUG-403，读者报的那条）**——
   **源码窗格里要立刻出现内容**，不是仍然空白。修复前标签数据里有、源码窗格不显示，
   而且**下一次敲键会把空白写回去**，答案就丢了。预览模式下看不出这个问题，
   一定要在**分屏或源码**模式下测

## 十一、插件用 HTML 画自己的界面（2026-09-10，FEAT-143）

`ui.webview` 从此有实现了。**这一条需要你写个小插件来试**，官方插件还没用到它。

### 54. 一个网页窗格画出来了

在插件目录里放一个最小插件（`manifest.json` 声明 `"permissions": ["ui.webview"]`，
`plugin.lua` 一行）：

```lua
function on_command(ctx)
  return { pane = "<h1 style='color:teal'>你好</h1>", title = "网页", as = "web" }
end
```

| 该发生什么 | 此前 |
|-----------|------|
| 文档旁边的窗格里画出一个青色的「你好」 | **没有任何办法打开网页**——权限在、文档在、代理在，就是没有实现 |

> **Linux 上会看到一句话**而不是页面：「…没有编辑器能用的网页引擎」。
> 这是预期的（见下方说明），不是 bug。

### 55. 没申请权限就画不出来

把上面 manifest 里的 `ui.webview` 换成 `ui.sidebar`，重新加载插件，再跑一次。

| 该发生什么 |
|-----------|
| 一句通知，说这个插件没有申请 `ui.webview`，并解释那是什么 |

### 56. 插件页面上列出了连带的权限

设置 → 插件 → 点开那个插件。

| 该发生什么 |
|-----------|
| 权限一栏除了「打开它自己的网页」，还列出**侧边栏**和**网络请求**——因为网页是以窗格出现的，而页面能自己联网。少列任何一条都是在低报你同意了什么 |

**顺便看这一页的语言（BUG-400）**：权限清单的 18 条描述现在该是**中文**
（或你选的任何语言）。修复前整份清单都是英文——而这正是你判断要不要装
一个陌生人写的插件时读的那一段。切一种语言再看一遍。

### 57. 页面访问了哪里，日志里有

把上面那行 HTML 换成会取远程图片的，比如
`<img src="https://example.com/a.png">`，打开窗格，然后看日志
（MCP 的 `read_logs`，或插件日志文件）。

| 该发生什么 |
|-----------|
| 一行 `webview <插件名> → https://example.com`。**只记到主机**，不记路径和查询串——那里可能带着你的文档内容 |

### 58. 不开它就不该有代价（这一条最要紧）

**先不要打开任何网页插件**，正常启动编辑器，看启动日志那三行
（第 35–38 条用的同样那几行）。

| 该发生什么 | 为什么要专门测 |
|-----------|--------------|
| 启动时间与常驻内存**和加这个功能之前一样** | 引擎是**按需创建**的。如果这里变慢或变胖，说明有东西在启动时就把引擎拉起来了，那与「秒启动、占用低」直接冲突，要报给我 |

## 十二、AI 的回答边生成边显示（2026-09-10，FEAT-144，读者提出）

### 59. 字是长出来的，不是一下子蹦出来的

1. 右侧栏点 AI 写作，回答问题，**盯着那块空白**

| 该发生什么 | 此前 |
|-----------|------|
| 文字一段段出现，几秒内就有东西可读 | **一直空着**，直到模型全部说完才整段蹦出来——读起来像命令没反应 |

2. **换成右键菜单的 AI 纠错**再看一遍：它的答案落在文档下方的窗格里，
   同样应当边到边显示
3. **中途关掉那个窗格**——不该有任何东西再把它塞回来（关闭就是「我不看了」）
4. **它必须停下来**（BUG-404）——生成结束后转圈动画要消失、「采用」按钮要出现。
   上线当天实测过一次十五分钟仍在转、日志无错的：那是因为当时只等 socket 关闭，
   而你的 provider 说完了并不关连接。现在读的是它自己发的结束标记。
   万一又卡住：**两行之间静默满 120 秒**就会停，已经吐出来的字保留，
   一个字都没有则报错，错误里会写「streamed N lines and no text」——
   把那个 N 告诉我，它能区分「线上一个字节都没来」和「来了但格式不认识」

> 插件那边一个字没改：它仍然只被调用一次、拿到完整答案。
> 所以你装的 0.1.4 也能看到流式效果，不用等插件发新版。

## 还没定的四件事

测的时候顺便看看，这几件需要你拿主意：

1. **行内代码紧贴背景**是否可接受（见第 2 条）
2. **`==标记==` 的底色和搜索命中是同一个黄**——在有标记的文档里搜索，分不清哪个是文档里写的、哪个是刚找到的
3. **那块底色硬编码成黄色，不跟主题走**——深色主题下配深色文字并不好读。真要改，这条比上一条更值得做，而且顺带解决它
4. **要不要给 `docx_creator` 报上游 issue**：它的 `_hasFormatting` 漏了 `shadingFill`，只设底色的 run 会被写成没有任何属性
