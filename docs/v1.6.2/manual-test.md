# v1.6.2 人工测试清单

自动化测试 2557 条全绿，`dart analyze --fatal-infos` 干净。**这份清单只列测试够不到的地方**——视觉、真实文件系统、真实插件、别的应用。纯内部收敛（围栏规则、配置解析等）不在这里，它们由测试和变异验证覆盖。

按「怎么造出这个场景 → 该看到什么」写，可以照着做。

---

## 一、看一眼就能判断的（视觉）

### 1. 打开 `code/test/fixtures/showcase.md`，切到源码视图

这一版给源码窗格加了五种以前不染色的标记。第 16 行那一行是关键：

```
~~strikethrough~~, ==highlight==, ^superscript^, ~subscript~, and a
```

**该看到**：`~~删除线~~` 有线，`==highlight==` 有黄底，`^superscript^` 和 `~subscript~` **仍然是普通文字**（有意的，源码窗格改不了字号）。

再看：`_下划线写的斜体_`、`__这样的粗体__`、`$E = mc^2$`（代码色）、`[^1]`（链接色）、`++下划线++`。

**要留意**：`snake_case_name` 这类标识符**不能**变成斜体。文档里出现价格 `$5` 和 `$10` 时，中间的文字**不能**被染成公式。

### 2. 行内代码的底色现在紧贴文字 ← **这条要你定**

以前 `` `code` `` 前后各加了一个空格来撑开底色。那两个空格是**内容**：会被一起复制走，而且打开查找框时它们就不加了——同一段文字在开不开查找框时长度不同。

现在去掉了，底色贴着字母。**如果你觉得太挤**，可以退回去，但要连带接受上面三个后果，或者改成 `WidgetSpan`（那样代码文字就选不中、搜不到了）。

### 3. 插件详情页多了一段「Permissions」

设置 → 插件 → 点一个已安装的插件。**该看到**：README 上方一段权限列表，每条是一句人话（"Read the open document and your selection"），不是 `document.read` 这样的标识符。

社区搜索结果的详情页**不该**有这一段——包还没下载，编辑器没见过它的 manifest。

## 二、要造场景才能验的

### 4. 装一个 manifest 有毛病的插件

随便改一个插件的 `manifest.json`：把 `"runtime": "lua"` 改成 `"perl"`，或者把 `entrypoints` 里的 `windows` 打成 `windwos`。

**该看到**：插件设置页在已安装列表**下方**出现「Installed but unreadable」，一行一个：目录名 + 具体原因（"unknown plugin runtime: perl"）。以前它是静默消失的，和从没装过一模一样。

### 5. 装一个什么权限都不声明的插件

把某个插件 manifest 的 `"permissions"` 改成 `[]`，然后用它。

**该看到**：它拿不到文档内容（看到的是空文档），开不了窗格，弹不了通知——而且**每次被拒时都会告诉你**缺哪一项，用一句人话加上标识符。

### 6. 制造一次磁盘冲突 ← **这条最要紧**

在编辑器里打开一个文件、改几个字**不要保存**；用别的程序（记事本、`echo x > 文件`）改同一个文件；回到编辑器等自动保存或按 Ctrl+S。

冲突横幅出来后，三个选择都要试：

- **「用我的覆盖」写不进去时**（可以把文件设成只读来造）：该弹出失败原因，**而且横幅要留着**。以前是横幅消失、磁盘上还是对方的版本——看起来像成功了
- **「用磁盘上的」读不了时**（把文件删掉再点）：该说为什么，而不是什么都不发生
- 状态栏点编码换一种重读，如果文件已经不在了：同样该说原因

### 7. 手工改坏配置文件

配置在系统应用支持目录下的 `config.json`。把任意一个 `true`/`false` 改成 `"yes"`，或者把 `"recentFiles"` 里塞一个数字进去。重启。

**该看到**：只有那一项回到默认，**其余设置全都还在**（主题、字体、快捷键、最近文件）。以前一个字符写错就全部重置。

## 三、要别的应用配合的

### 8. 导出 Word，看 `==高亮==`

写一行 `==标出来== ^上标^ ~下标~ ++下划线++ ~~删除线~~ \`代码\``，导出 .docx，用 Word/LibreOffice 打开。

**该看到**：高亮是黄色荧光笔（以前它**完全没有底色**，是这一版修的），其余五种各自的样式都在。

### 9. 从网页复制粘贴

找一个带 `<mark>`、`<sup>`（维基百科的脚注引用就是）、`<u>` 的页面，复制一段粘进编辑器。

**该看到**：它们变成 `==...==`、`^...^`、`++...++`，而不是丢掉标记只剩字。**含空格的短语**（`<sup>the note above</sup>`）应该保持纯文本——那种写法编辑器自己读不回来。

这一版重写了粘贴前剥掉注释和 `<script>`／`<style>` 的那两段（原来是正则，在畸形输入上是二次方）。**自动测试用的是我构造的 HTML**，而浏览器真正放进剪贴板的东西不一样：Windows 会包一层 `HTML Format` 头，Chrome 会插 `<!--StartFragment-->` 这样的标记，页面本身还常带内联样式表。所以这一条要用**真实的浏览器复制**，不要用手写的 HTML 片段。

**该看到**：粘进来的是正文，没有 `StartFragment` 之类的碎片标记，也没有整段 CSS 混进文字里。多试一个样式表在正文之前的页面（多数新闻站是这样）。

### 10. 复制含公式或图片的段落，粘到 Word

在预览里选中一整段（段落里要有 `$E = mc^2$` 或一张图或 `` `代码` ``），复制，粘到 Word。

**该看到**：粗体、链接、标题都在。以前只要段落里有这些，**整段的格式全丢**，只剩纯文本。

### 11. 从源码窗格复制带 HTML 标签的文字

设置里**关掉**「行内 HTML」。源码里写 `a <b>tagged</b> word`，从源码窗格选中复制，粘到 Word。

**该看到**：`<b>` 是字面文字，和预览里一致。以前从源码窗格复制会变成粗体，从预览复制不会——同一段源码，取决于你在哪个窗格里拖的鼠标。

---

### 12. 退出应用，看 trace 日志

关掉应用，打开配置目录里的 `startup-trace.log`，看最后一次运行的末尾。

**该看到**：`window destroyed` 之后就结束了。**不该看到** `still running 100ms after close began` 这类行——那说明关闭看门狗没被撤下，而它在 600ms 时会 `exit(0)`，抢在正常退出前面。

## 还没定的四件事

测的时候顺便看看，这几件需要你拿主意：

1. **行内代码紧贴背景**是否可接受（见第 2 条）
2. **`==标记==` 的底色和搜索命中是同一个黄**——在有标记的文档里搜索，分不清哪个是文档里写的、哪个是刚找到的
3. **那块底色硬编码成黄色，不跟主题走**——深色主题下配深色文字并不好读。真要改，这条比上一条更值得做，而且顺带解决它
4. **要不要给 `docx_creator` 报上游 issue**：它的 `_hasFormatting` 漏了 `shadingFill`，只设底色的 run 会被写成没有任何属性
