## FEAT-077：构件互不干扰

| 字段 | 内容 |
|------|------|
| 实现日期 | 2026-09-01 |
| 需求描述 | 把「一种构件不得被旁边的构件弄坏」这条性质做成可执行的测试 |
| 用户场景 | 真实文档从来不是单一构件。BUG-215（引用块之后所有引用式链接失效）就是这么产生的，而规范语料完全抓不到 |
| 优先级 | P2 |
| 难易度 | 低 |

### 缘由

BUG-215 的教训：**CommonMark 语料每个例子只有一种构件**，
解析器可以全部通过，而把两种构件放进同一篇文档就出错。
那个 bug 修复前后规范分数都是 493，纹丝不动——语料里没有一个例子同时含有
引用块和引用式链接。

### 实现方案

19 种构件，每种给出「源码」和「输出里必须出现的特征」。
遍历**全部三元有序组合**（5814 种），拼成文档解析导出，
断言三种构件的特征都还在。

**特征刻意取得宽松**——取构件承载的文字，而不是精确的标签。
两个相邻列表会合并成一个松散列表（这是正确行为），
条目于是从 `<li>x</li>` 变成 `<li><p>x</p></li>`；
特征写死成前者就会在**正确的输出**上误报。

**前置元数据单独验**：它只有在文件最开头才成立，
放进遍历会产生 19 条假阳性。另外补了一条反向断言——
写在文档中间的 `---\ntitle: 甲\n---` **不应该**被当成前置元数据。

### 验收标准

- 5814 个三元组合全部通过
- 撤掉 BUG-215 的修复后，这条测试必须失败（实测 147 个组合报错）
- 单次运行 < 10 秒（实测 7.7 秒）

### 本轮的排查结论

- 全部三元组合**零失败**，构件互扰这一维度目前是干净的
- 顺带核对了解析器的可变实例状态：只有 `_linkDefinitions` 与 `_parseDepth` 两个，
  都已在 BUG-215 中处理，没有第二处会被嵌套解析破坏的状态

### 涉及文件

- `code/test/services/constructs_do_not_interfere_test.dart`（新增，3 条测试 / 5814 个组合）

## FEAT-078：导出的过程与结果都要说出来

| 字段 | 内容 |
|------|------|
| 实现日期 | 2026-09-01 |
| 需求描述 | 导出进行时告诉用户在忙什么，完成后告诉用户文件写到了哪里 |
| 用户场景 | 选完文件名之后，窗口静默冻住几秒，然后什么也没发生——文件其实已经写好了，但用户无从判断 |
| 优先级 | P2 |
| 难易度 | 低 |

### 缘由

本轮在核对「支持大文件」时量了导出的耗时：

| 文档 | HTML | PDF | Word |
|---|---|---|---|
| 6 K 字符 | 173 ms | 720 ms | 128 ms |
| 28 K 字符 | 93 ms | 1003 ms | 226 ms |
| 117 K 字符 | 225 ms | **3043 ms** | 546 ms |

PDF 大致线性增长，外推到 1 MB 约 26 秒。查代码发现：
**失败会弹提示，成功什么也不说，过程中也没有任何进度指示。**
于是大文档导出时，用户看到的就是一个毫无解释的假死窗口。

### 实现方案

`runExport(fileName, work)`：显示一个不可关闭的模态提示 →
让出一帧确保它先画出来 → 执行导出 → 关闭提示 →
成功弹「已导出到 xxx」，失败走原有的失败提示。
HTML / PDF / Word 三个入口统一改为委托给它。

**一处必须诚实说明的局限**：PDF 导出的繁重部分跑在主 isolate 上，
所以转圈动画在那段时间里**不会转**。这个改动给到的是
「一个说明自己在忙什么的窗口」，而不是「一个看起来死掉的窗口」——
真正的修法是把导出挪到独立 isolate，那是更大的改动（字体加载、
Mermaid 图片渲染都在主 isolate），留作后续。

### 一条守卫测试的调整

既有的 `export_failure_test` 用源码扫描保证「导出处理器必须捕获异常」，
它检查的是**机制**（函数体里要有 `try` 和 `reportExportFailure`），
改成委托后这条就失败了。

按**意图**重写：本地捕获**或**委托给 `runExport` 都算合格。
但这样会开一个口子——万一委托目标什么都不做呢？
所以**同时补了一条测试，验证 `runExport` 确实上报失败、也确实说明去向**。
没有这条，放宽就成了漏洞。

### 验收标准

- 三个导出入口都经由 `runExport`
- 12 种语言都有「正在导出…」与「已导出到 {file}」，且后者带上文件名
- 守卫测试仍然能挡住「新增一个不报告失败的导出入口」

### 涉及文件

- `code/lib/app.dart`、`code/lib/ui/widgets/app_menu_bar.dart`
- `code/lib/core/i18n/l10n/app_*.arb`（12 种语言）及生成代码
- `code/test/ui/widgets/export_failure_test.dart`（守卫改按意图检查，新增 2 条）
